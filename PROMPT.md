# Тотальный промпт: приложение для бургерной (Burger Shop)

Скопируйте всё ниже в новый чат целиком.

---

Ты senior-разработчик и дизайнер мобильных интерфейсов. Создай веб-приложение для небольшой бургерной в Нячанге (Вьетнам). Цены в донгах (₫), интерфейс на русском. Пользователь работает с телефона одной рукой, часто в спешке: всё должно быть максимально простым, читаемым и без лишних шагов.

## 1. Технические рамки
- Один файл `burger-app.html` (HTML + CSS + JS), без сборки и внешних библиотек, без CDN. Работает офлайн.
- Данные хранятся в `localStorage` (ключ `burger-app-v2`, один JSON). Любой ввод и клик сразу сохраняется.
- Адаптив: телефон (от 360 px) главный. От 860 px касса и очередь заказов показываются рядом.
- Установка как приложение (PWA): `manifest.webmanifest` (standalone, портрет, иконки 192/512/maskable), `sw.js` (стратегия «сеть сначала, офлайн из кэша»), `apple-touch-icon`, иконка с эмодзи 🍔 на терракотовом фоне, `index.html` с редиректом на приложение.
- Публикация через GitHub Pages. В файле `<meta name="app-version">` с номером версии, который повышается при каждой публикации.

## 2. Дизайн-правила (важнее красоты — читаемость)
- Две темы: светлая и тёмная. Кнопка 🌙/☀️ в шапке, выбор запоминается. Пока не выбрано, следовать настройке устройства. Все цвета через CSS-переменные, отдельно подобранные для тёмной темы. Контраст текста не ниже WCAG AA. Поля ввода, даты и подсказки (placeholder) читаются в обеих темах (`color-scheme`).
- Палитра: тёплый светлый фон, тёмный текст, приглушённый терракотовый акцент (`#b84d1f`, в тёмной `#e8825a`). Статусы: зелёный, жёлтый, красный, синий.
- Базовый шрифт 14 px, текст не мельче 12 px, кнопки не ниже 44 px по высоте. Настройка «Размер интерфейса»: Мелкий (0,85), Средний (0,92, по умолчанию), Крупный (1,0) через `zoom`, выбор запоминается.
- Ничего не должно переноситься по словам внутри денежных сумм. Длинные названия не ломают строки: заголовок и кнопки в одну строку с переносом на следующую при нехватке места.
- Никаких окон «Вы уверены?». Вместо них уведомление с кнопкой «Отменить» (откат любого действия 5 секунд). Единственное исключение: «Сбросить все данные» требует нажать дважды.
- Нижняя навигация из 5 вкладок с красными счётчиками. Учитывать `safe-area-inset`.

## 3. Вкладки и функции

### 3.1 Заказы
- Касса: плитки блюд (эмодзи, название, цена). Нажатие добавляет, кнопка «−» убирает, бейдж с количеством. Блюдо в стоп-листе недоступно.
- Плашка корзины внизу → окно оформления: состав со степпером, имя клиента или стол, «На месте / С собой», комментарий («Без лука»), итог, кнопка «Создать заказ».
- Очередь: фильтры-чипы со счётчиками по статусам. Статусы: Новый → Готовится → Готов → Продан. Одна главная кнопка на следующий статус и «✕» отмены. Таймер «N мин назад», красная подсветка заказов старше 15 минут. Цветная полоса слева по статусу.
- На телефоне два подэкрана «➕ Новый заказ» и «🧾 Очередь», на широком экране оба рядом.
- Когда заказ получает «Продан», продукты списываются со склада по тех. карте. Отмена продажи возвращает их. Списанное записывается в заказ (`deducted`) для точного отката. Остаток не уходит ниже нуля.

### 3.2 Продажи
- Фильтр «Сегодня / 7 дней / Всё время»: число заказов, выручка, средний чек, прибыль (оценка по себестоимости), топ блюд с полосками, история проданных (последние 20).
- Выручка за сегодня всегда видна в шапке.
- «Скопировать таблицу (CSV)» в буфер обмена (скачивание может быть запрещено).
- «Загрузить демо-данные» (см. раздел 5), с откатом.

#### Финансы (подвкладка на вкладке «Продажи»: «🧾 Продажи» / «📊 Финансы»)
- Период: Сегодня / 7 дней / Месяц (30 дней) / Всё время.
- Карточки: выручка, себестоимость продаж, валовая прибыль и чистая прибыль с процентом от выручки.
- «Как считается прибыль»: выручка − себестоимость = валовая прибыль; − расходы на работу (аренда, зарплата, коммуналка, реклама, связь, оборудование, налоги, прочее) = чистая прибыль. Закупка продуктов в прибыль не вычитается, чтобы не считать дважды.
- «Движение денег»: приход (выручка и прочее), расход (закупка продуктов и работа заведения), итог по деньгам.
- «Выручка по дням»: столбчатая диаграмма, выходные другим цветом, лучший день и средняя выручка.
- «Расходы по статьям» с долями и «Прибыль по блюдам» (штук, выручка, себестоимость, прибыль, маржа).
- Журнал приходов и расходов с удалением (с откатом) и форма добавления операции (тип, статья, сумма, комментарий). Данные: `S.fin = [{ id, ts, type('in'|'out'), cat, note, sum }]`.

### 3.3 Меню
Переключатель: «Блюда и цены» / «Технологические карты».
- Блюда: двухэтажная строка (сверху эмодзи + название, переключатель «Есть» (стоп-лист) и «Удалить», ниже поля «Цена» и «Себестоимость»). Если у блюда есть тех. карта, себестоимость считается из неё. Добавление нового блюда.
- Тех. карты: состав (название, количество, единица г/мл/шт, КБЖУ на 100 г/мл или на 1 шт, цена за кг/л/шт, привязка к позиции склада, вес 1 шт), технология, время приготовления. Автоматический расчёт: выход, ккал/Б/Ж/У на порцию и на 100 г, себестоимость, фудкост (% от цены), наценка. Редактор в нижней шторке.
- Внизу вкладки:
  - «Размер интерфейса».
  - «Обновление»: показывает версию, кнопка «Проверить обновления» сравнивает версию на сайте с текущей (запрос без кэша), при отличии сохраняет данные и перезагружает. Также тихая проверка через 1,5 с после запуска. Если корзина не пуста, только подсказка, без перезагрузки.
  - «💾 Резервная копия» (свёрнутый спойлер `<details>`): скачать JSON-файл, скопировать текстом, восстановить из файла, восстановить из вставленного текста. Проверка структуры, откат восстановления, дата последней копии.
  - «Сбросить все данные».

### 3.4 Заготовки
- Позиции: название, остаток, норма на смену, размер партии, срок годности (дни), дата истечения (конец дня).
- Сортировка по срочности: просрочено, истекает сегодня, истекает завтра, годно до даты, нет в запасе. Цветные бейджи, шкала заполнения, «заготовить ещё N».
- Кнопки: «+ Заготовил партию» (новая партия не продлевает более ранний срок), «− Израсходовано», «Списать», редактирование даты, удаление. Две карточки-счётчика сверху: «Нужно заготовить» и «Срок на исходе».

### 3.5 Склад
- Остатки с «−/+» (шаг 10 для штук, 0,5 для кг и л), бейдж «Мало / В норме», минимум.
- Жёлтая плашка «Пора закупить».
- «🛒 Список покупок»: для позиций ниже минимума считается докупить до двойного минимума (штуки округляются до целых, остальное до 0,5). У каждой строки кнопка «Купил» (добавляет к остатку, с откатом). Кнопка «Скопировать список» (текст с маркерами для мессенджера).
- Добавление новой позиции (название, остаток, единица, минимум).

## 4. Модель данных
```
S = {
  menu:   [{ id, em, name, price, cost, on, tc: { time, steps, ings: [
              { name, qty, unit('г'|'мл'|'шт'), kcal, p, f, c, price, stockId, w } ] } }],
  stock:  [{ id, name, qty, unit, min }],
  preps:  [{ id, name, qty, unit, par, batch, shelf, exp }],
  orders: [{ num, client, type('here'|'go'), note, status('new'|'cook'|'ready'|'sold'),
             items: [{ id, name, price, cost, qty }], created, sold, deducted: [[stockId, amount]] }],
  seq:    { menu, stock, order, prep }
}
```
Расчёты: КБЖУ на 100 г/мл (для штук на 1 шт); выход = сумма г и мл + шт × вес; себестоимость = Σ(кол-во/1000 × цена) для г и мл, кол-во × цена для шт; списание г→кг, мл→л, шт→шт. При загрузке старых данных мигрировать недостающие поля.

## 5. Демо-данные (полноценная демонстрация работы)
Кнопка заменяет все данные демо-набором (с откатом), генерация детерминированная (seed):
- 8 блюд с тех. картами, составом и КБЖУ: Классический, Двойной, Овощной, Картофель фри, Чизбургер, Бекон-бургер, Чикен-бургер, Кола 0,33.
- Склад из 14 позиций, часть ниже минимума, чтобы сразу появлялся список покупок.
- 7 заготовок с разными сроками: просроченная, истекающая сегодня и завтра, далёкая, закончившаяся.
- История продаж за 30 дней: выходные загружены больше, пики в обед и вечером, вьетнамские и русские имена, столы, примечания, популярные блюда по весам.
- Финансы за 30 дней: аренда, две выплаты зарплаты, коммунальные, реклама, интернет, налоги, ремонт, закупки продуктов каждые 3 дня (по себестоимости проданного), стартовый взнос в кассу и прочий приход.
- 6 живых заказов в очереди (2 новых, 2 готовятся с одним просроченным, 2 готовы).
