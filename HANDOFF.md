# Burger Shop: передача проекта (handoff)

Документ для переноса в новый репозиторий и новый чат. Всё, что нужно, чтобы продолжить с нуля без потери контекста.

## 1. Что это и для кого

Приложение для небольшой бургерной (Нячанг, Вьетнам, цены в донгах ₫). Основной пользователь работает с телефона: принимает заказы, смотрит продажи, ведёт меню, заготовки и склад. Язык интерфейса: русский.

Главная задача: максимально простой учёт заказов (CRM) и продаж, плюс понятная работа с заготовками, сроками годности, составом блюд и КБЖУ.

## 3. Что умеет `burger-app.html`

Пять вкладок в нижней панели:

1. **Заказы.** Касса: плитки блюд (нажатие добавляет, «−» убирает), плашка корзины, оформление (имя или стол, «На месте / С собой», комментарий). Очередь: фильтры по статусам со счётчиками, таймер, красная подсветка заказов старше 15 минут. Статусы: Новый → Готовится → Готов → Продан. Любое действие откатывается кнопкой «Отменить» в уведомлении.
2. **Продажи.** Фильтр «Сегодня / 7 дней / Всё время»: число заказов, выручка, средний чек, прибыль (оценка), топ блюд, история, копирование CSV в буфер, загрузка демо-заказов.
3. **Меню.** Два режима:
   - «Блюда и цены»: цена, себестоимость, стоп-лист («Есть»), добавление и удаление блюд.
   - «Технологические карты»: состав, КБЖУ на порцию и на 100 г, выход, себестоимость, фудкост, наценка, время и технология. Себестоимость блюда берётся из карты, если она заполнена.
4. **Заготовки.** Остаток, норма на смену, «заготовить ещё N», шкала, срок годности (Просрочено / Истекает сегодня / Истекает завтра / Годно до), кнопки «+ Заготовил партию», «Израсходовано», «Списать», редактирование даты.
5. **Склад.** Остатки с «+/−», пометка «Мало», список «Пора закупить».

Связи между разделами: когда заказ получает статус «Продан», продукты списываются со склада по тех. карте. Отмена продажи возвращает их.

Тема: светлая и тёмная по настройкам устройства. Интерфейс адаптивный: на телефоне нижняя навигация, от 860 px касса и очередь рядом.

## 4. Модель данных

Всё хранится в `localStorage`, ключ `burger-app-v2`, один JSON:

```
S = {
  menu:   [{ id, em, name, price, cost, on, tc: { time, steps, ings: [
              { name, qty, unit('г'|'мл'|'шт'), kcal, p, f, c, price, stockId, w } ] } }],
  stock:  [{ id, name, qty, unit, min }],
  preps:  [{ id, name, qty, unit, par, batch, shelf(дней), exp(timestamp конца дня) }],
  orders: [{ num, client, type('here'|'go'), note, status('new'|'cook'|'ready'|'sold'),
             items: [{ id, name, price, cost, qty }], created, sold, deducted: [[stockId, amount]] }],
  seq:    { menu, stock, order, prep }
}
```

Правила расчёта:
- КБЖУ ингредиента задано на 100 г или 100 мл, для штучных на 1 шт. Выход блюда: сумма г и мл плюс шт × вес 1 шт.
- Цена ингредиента: за кг, литр или штуку. Себестоимость = Σ (количество / 1000 × цена) для г и мл, количество × цена для шт.
- Списание со склада: г → кг, мл → л, шт → шт. Остаток не уходит ниже нуля. Что именно списано, записывается в `order.deducted` для точного отката.
- Срок годности: `exp` это конец дня. Статус считается от текущего времени. Новая партия не продлевает срок, если остаток уже есть и срок раньше.

## 5. Принятые решения (чтобы не пересматривать заново)

- Один HTML-файл без сборки и внешних библиотек: работает офлайн, открывается с GitHub Pages или как приложение с экрана «Домой».
- Подтверждений «Вы уверены?» нет: везде откат через уведомление. Исключение: «Сбросить все данные» (нажать два раза).
- Старые вкладки «Смена», «Обзор», «Финансы» убраны как дублирующие и с зашитыми цифрами. БЖУ и составы блюд, которые были просто справочником, теперь живут в тех. картах.
- Палитра: тёплый светлый фон, тёмный текст, приглушённый терракотовый акцент; в тёмной теме все цвета заданы отдельно и проверены на контраст. Пользователь прямо жаловался, что цифры и текст не видны, поэтому контраст важнее красоты.
- Минимум 44 px на кнопках, текст не меньше 12 px.
- Данные примеров (меню из 4 блюд, склад, заготовки, составы) вымышленные и ориентировочные. Их нужно заменить реальными.

## 6. Известные ограничения

- Данные живут в браузере одного устройства. Нет общей базы: кассир и повар на разных телефонах не видят одну очередь.
- Нет входа и ролей, нет резервной копии (кроме копирования CSV по продажам).
- Заготовки не связаны с тех. картами и складом: они только показывают остаток и срок.
- Нет печати чеков, нет оплат (наличные, карта, перевод), нет скидок.
- Нет учёта вьетнамского формата чека и налогов.
- Живая приватная ссылка на claude.ai открывается только владельцем. Скачивание файлов в ней отключено, поэтому экспорт сделан копированием в буфер.

## 7. Что делать дальше (по приоритету)

1. **Общая база данных** (чтобы очередь была общей для всех устройств). Варианты: Supabase или Firebase (проще всего), либо маленький сервер. Нужен выбор пользователя.
2. **Оплаты и закрытие смены**: способ оплаты, наличные в кассе, итоги смены, расхождения.
3. **Связать заготовки с картами и складом**: полуфабрикаты (соус, котлеты) как ингредиенты карт, списание заготовок при продаже.
4. **Резервная копия и импорт**: выгрузка и загрузка всех данных в файл.
5. **Закупки**: список закупки по минимумам склада и по плану заготовок.
6. **Установка как приложение (PWA)**: манифест и иконка, чтобы добавлялось на главный экран.
7. **Отчёты**: продажи по часам и дням недели, списания, динамика фудкоста.

## 8. Как запускать и публиковать

- Локально: открыть `burger-app.html` двойным щелчком, ничего устанавливать не нужно.
- GitHub Pages: Settings → Pages → источник выбрать основную ветку и корень. Тогда файл будет по адресу `https://godoffear.github.io/<репозиторий>/burger-app.html`. Если переименовать файл в `index.html`, он станет главной страницей.
- Проверка в браузере без вмешательства в код: открыть файл, на вкладке «Продажи» нажать «Загрузить демо-заказы».

## 9. Как дать новому чату полный доступ к репозиторию

Сам я этого сделать не могу, это делается на вашей стороне:

1. Создайте новый пустой репозиторий на GitHub (например, `burger-shop`).
2. Установите приложение Claude на этот репозиторий: https://github.com/apps/claude/installations/select_target (нужно выбрать нужный репозиторий и подтвердить).
3. В новом чате на claude.ai/code выберите этот репозиторий как источник сессии.
4. Чтобы чат мог сам создавать PR и вливать изменения без вопросов, в начале напишите это прямо: «Можно коммитить в основную ветку и вливать PR без отдельного подтверждения». Принудительную перезапись истории (force push) лучше не разрешать.
5. Не отправляйте токены и пароли в чат: хватает установленного приложения.
